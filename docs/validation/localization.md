# Android translation validation

The shared string source is `openwatersio/slackwater-ios` merge commit `02188f2a2f5ef4166cd74c373a5885736d7ef159` (PR #900). Product documents, resources and recipe evidence use that immutable merge commit; the exporter reads the tree with `git show` rather than the checkout's moving HEAD.

`scripts/strings-map.json` maps 228 shared resources; 70 explicit Canadian French migration overrides retain the wording already used by the app and its PDF tests. The Android-only translation sources contain 216 more resources per locale, including plural and array resources. English wording and existing Canadian French copy are retained; other Android-only translations are new. The generated locale configuration exposes all 16 locales in Android's app language settings.

## Automated checks

`node --test scripts/*.test.mjs` covers positional argument conversion, numeric types, literal percentages, plural categories, apostrophe/XML escaping, Unicode, regional locale mapping, missing translations, preservation of handwritten XML and freshness against an immutable Git tree. Android compilation and lint check the complete packaged resources. `node scripts/export-strings.mjs --check` verifies committed resources and their source provenance; CI runs the same check after source sync.

`LocalizationTest` selects every locale through Android configuration contexts, checks locale-specific resource selection, formats string and plural arguments, and renders the production list and tide detail at 1.3× font scale. This test captures screenshots when passed `screenshots=true`; it does not change the emulator's system locale. An external Gradle init script can set a separate application ID for running alongside another development build.

## Evidence and limits

On November 6, 2026, all 48 `LocalizationTest` cases passed on an ARM64 Pixel emulator running API 37 (Android 17, build `CE2A.260420.051.A2`), 1080×2400 pixels at 420 dpi. The test used 1.3× font scale and the isolated package `io.openwaters.slackwater.android.translations`. Each locale selected its own shared and Android-specific strings, rendered the list and tide detail, and formatted plural/number arguments. The French (France) and Spanish (Mexico) contexts resolved to the shipped Canadian French and Spanish (Spain) resources. The channel-name check verified that re-registering an existing channel updates its translated name.

All 32 list/detail screenshots were visually inspected. Longer headings and descriptions wrap; long station names use the existing ellipsis policy. An Irish detail screenshot was retaken after its first capture preceded the commentary draw.

The 14 Node tests, source/export freshness checks, `:core:test`, `:app:testDebugUnitTest`, `:app:lintDebug` and `:app:assembleRelease` passed. The existing list/PDF/query-layout run exposed cached station-list state racing its test reseed. The fixture waits for the cleared state and then the seeded favorite order before interacting. All 13 integrated device regressions pass in two consecutive combined runs, covering calendar publishing/removal, notification/calendar-name localization, French PDFs, station lists and shortcut layout. Calendar availability evaluates a full forecast horizon; its functional test uses the same 90-second bound as publishing. A diagnostic availability query took about 23 seconds on this emulator. No production persistence behavior changed.

API 26 was not run locally; the existing CI matrix runs API 26 and 37. Native-speaker editorial review is separate from these resource and layout checks. These checks cover the resource-backed UI, the shipped list and bundled tide detail; they do not replace TalkBack, every dialog, translated PDF pagination, tablet/foldable or all large-font checks tracked in #27. None of the current shipped locales is an RTL language. Native-speaker review of the new Android-only translations, particularly Irish and Scottish Gaelic nautical and astronomical terms, remains a release editorial check.

Notification event labels, heights and station-local times use the configured language, as do calendar display names. English notification sentences retain their standalone event wording. Calendar names and notification channel names refresh during normal reconciliation/access; they do not promise an immediate system-settings refresh on a locale switch. Generated Calendar Provider event titles and notes remain in English: the pinned reconciliation contract uses title/alarm agreement to identify existing rows. Translating those persisted records requires a separate identity migration so a locale change cannot replace rows or change provider IDs.
