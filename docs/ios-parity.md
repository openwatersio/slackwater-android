# Android parity with Slackwater iOS

Android verification is tracked in the [scenario and accessibility matrix](validation/accessibility.md), the [station detail checks](validation/station-detail.md), the [timeline fixtures and interruption trace](validation/timeline.md), and the [performance evidence ledger](validation/android-performance.md).

This ledger is the acceptance map for the Android work tracked in [repository issues](https://github.com/openwatersio/slackwater-android/issues) and the [Slackwater Android project](https://github.com/orgs/openwatersio/projects/5); each row names the issues that own it. Its source is the entire iOS tree at [PR #921 merge commit `6457d71b46af0e1c3310e1f8688dffc0db102d33`](https://github.com/openwatersio/slackwater-ios/tree/6457d71b46af0e1c3310e1f8688dffc0db102d33). Rows describe work to implement and verify, not existing Android features.

Use the owning product document when its wording differs from incidental iOS code. Source documents that point to moving upstream links must be resolved to reviewed dependency SHAs in `upstream.lock.json` before implementation. Refresh this baseline deliberately; do not make CI compare a pinned export with the latest unreviewed iOS `main`.

## Android adaptations

These are deliberate Android product decisions. Add device evidence and user-facing wording before release; do not advertise Apple capabilities under an Android label.

| Area | Android choice and limit | Verification |
|---|---|---|
| UI/navigation | Compose and native Back/gesture behavior; dp/sp, 48 dp accessible control targets, TalkBack timeline adjustment in five-minute steps and next/previous-event actions. Keep a semantic event table behind every Canvas chart. | All source scenarios plus text scaling, reduced motion, keyboard/RTL chronology, tablets/folds. |
| Personal state | Device-local favorites, recents, namesakes, settings, rules and free day. Play purchases restore through the Play account; Apple purchases/free-day starts do not sync. No new Slackwater account is introduced. | Backup/restore behavior, restart and migration tests; precise store copy. |
| Downloads | Existing Kotlin IWLS client plus cancellable persisted chunk work. A client retry can outlast a worker; use bounded attempts and resumption, with foreground progress for explicit downloads. OS scheduling can delay continuation. | Real device interruption/quota/Data Saver tests; current [background-work guidance](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running). |
| Reminder delivery | Notification permission and exact-alarm access are separate. ### Android saved places

Favorites and recents share one device-local DataStore file so unstarring a station and moving it to Recents commit together. Both lists survive process restarts. The file lives in the no-backup directory, so moving to another device starts with empty lists. Corrupt or newer-format data stays on disk. A collector receives a failed result and can collect again to retry after a transient read failure.

### Android reading preferences

Height units, speed unit, set format and the comfort current live in their own device-local DataStore file in the no-backup directory. Stored values are the ones iOS and the web use (`imperial`/`metric`, `kn`/`kmh`/`ms`, `compass`/`degrees`). Height units stay unsaved until the person picks them, so the default follows the device region: imperial in the US, metric elsewhere. The comfort current is rounded half away from zero to a tenth of a knot within 0–10 kn, and zero turns the slack window off. Setting a value past either end keeps the nearest end; a stored value outside the range reads as 0.5 kn. A value this build cannot read stays on disk and reads as the default until the person picks another. A corrupt file is replaced with defaults, which also drops any settings a newer build stored there, so the settings stay writable; a file that cannot be read emits a failure, and a collector can collect again to retry.

### Android list preferences and location

The series filter, the record that the list has raised the location prompt and the record that the first-run tour was seen live in their own device-local DataStore file in the no-backup directory. An install that asked for location before the tour existed reads as having seen it. A corrupt file is replaced with defaults, which costs at most one tap, one prompt or one tour; unlike saved places, nothing in it is worth keeping unreadable. Slackwater keeps the device fix in memory. OpenFreeMap receives the requested tile coordinates and the device’s network address when the map loads. Automatic downloads start on app launch. Tile requests can reveal the coarse grid around a fix and the detail areas around favorites, recents, and downloaded stations. Revocation or expiry of a one-time grant drops vicinity held only for the fix once station inputs are readable. MapLibre retains downloaded packs and may cache tiles for viewed areas on device.

The location slot's states are pure functions in `core`, tested without a device. Two device tests also drive the framework providers through Android test providers: they grant location and the mock-location app-op and leave the grant in place, because revoking a runtime permission ends the test process, so later tests in the same run start with location allowed and must seed permission state through a fake source.

### Android model store

Fitted models, tide previews and online current windows are JSON records, one file per station and kind under `models/` in the no-backup directory, which keeps them out of cloud backup and device transfer. Each record carries `schemaVersion` and `stationId`. A write goes to a temporary file, is synced, and replaces the old file by rename, so a widget reading during a replacement sees the old record or the new one. A fit cancelled before the rename leaves the old record; once the rename lands, observers are told even if the caller was cancelled. Records keep fields this build does not know, so a new field that describes the fit or its data needs a new `schemaVersion`. A merge such as adding blocks to an online window reads and writes under one lock, so two concurrent fetches cannot drop each other's blocks. Removals are synced like writes. A file that does not parse or cannot be opened, names another station, or has a version outside the ones this build reads is reported unavailable and stays on disk until a new fit replaces it. A build never writes a record stamped with another version. A record stays under the ID it was fitted for and is never read for that station's successor, whose datums can differ. Saved places do not depend on models, so a missing or unreadable model never removes a favorite.
